# LIS（最长递增子序列）

> Longest Increasing Subsequence：保序不连续的最长严格递增子序列。两条路线 —— DP `O(n^2)`，patience sorting（贪心 + 二分）`O(nlogn)`

[查看实现与示例](./index.ts)

在 `coding/algorithm/` 子包内使用 Node >= 22.18 运行：

```bash
pnpm lis
```

对比 DP 与贪心二分的长度结果，并观察递增子序列重建。

## 1. 定义与性质

- 子序列：保序可不连续；连续的叫子串 —— LIS 研究子序列
- 严格递增与非递减：DP 的比较分别为 `<` 与 `<=`；贪心二分分别找第一个 `>= x` 与 `> x`，重复值能否延长序列由此决定
- DP 的依据：以 i 结尾的 LIS 只依赖「更靠前且更小」的结尾 —— 最优子结构 + 无后效性
- patience sorting 的依据：长度为 k 的递增子序列，结尾越小越「有潜力」接住后续元素

## 2. 方法一：动态规划 `O(n^2)`

状态 `dp[i]` = 以 `nums[i]` 结尾的 LIS 长度。先初始化为 1；有符合条件的前驱时，再取以下候选的最大值。空输入长度为 0，非空答案至少为 1：

$$
dp[i] = \max(dp[j] + 1),\quad j < i,\ nums[j] < nums[i]
$$

以 `nums = [10, 9, 2, 5, 3, 7, 101, 18]` 为例：

| i     | 0   | 1   | 2   | 3   | 4   | 5   | 6   | 7   |
| ----- | --- | --- | --- | --- | --- | --- | --- | --- |
| nums  | 10  | 9   | 2   | 5   | 3   | 7   | 101 | 18  |
| dp[i] | 1   | 1   | 1   | 2   | 2   | 3   | 4   | 4   |

- 答案是 `max(dp)` 而非 `dp[n-1]`：LIS 未必以最后一个元素结尾
- 内层扫描全部前驱是 `O(n^2)` 的根源 —— patience sorting 用二分把它消掉
- 方案重建：转移时记 `prev[i] = j`，从最大值处回溯

## 3. 方法二：贪心 + 二分（patience sorting）`O(nlogn)`

名字来自纸牌游戏 Patience：逐张发牌，牌只能压在比它大的最左堆顶上，最终堆数就是 LIS 长度。

维护 `tails` 数组：`tails[k]` = 所有长度为 k+1 的递增子序列中最小的结尾：

- 新元素 x：二分找 tails 中第一个 `>= x` 的位置替换，没有则追加
- 替换不破坏 tails 有序性（x 只替换一个 `>= x` 的值），所以每一步都可二分
- `tails.length` 就是 LIS 长度
- 严格递增用 lower bound（替换第一个 `>= x`）；非递减改用 upper bound（第一个 `> x`）
- 复杂度：n 次二分，每次 `O(logn)`

同一输入的发牌过程：

| x   | 二分位置       | 动作 | tails 之后     |
| --- | -------------- | ---- | -------------- |
| 10  | 0（空数组）    | 追加 | [10]           |
| 9   | 0（10 >= 9）   | 替换 | [9]            |
| 2   | 0（9 >= 2）    | 替换 | [2]            |
| 5   | 1（2 < 5）     | 追加 | [2, 5]         |
| 3   | 1（5 >= 3）    | 替换 | [2, 3]         |
| 7   | 2（3 < 7）     | 追加 | [2, 3, 7]      |
| 101 | 3（追加）      | 追加 | [2, 3, 7, 101] |
| 18  | 3（101 >= 18） | 替换 | [2, 3, 7, 18]  |

两个易错点：

- tails 不一定是 LIS：`[1, 3, 5, 2]` 处理完 tails = `[1, 2, 5]`，而 2 在原串中位于 5 之后 —— 它只是「各长度最优结尾」的集合，只有长度可靠
- 因此只要长度时，不要试图把 tails 当答案输出

要直接输出一条 LIS，仍然 `O(nlogn)`：发牌时记录每张牌的堆号 `pile[i]` 与前驱牌号 `prev[i]`（左侧相邻堆的当前堆顶 `topIndex[lo-1]`，不是被它替换的同堆牌），最后从最右堆的堆顶沿 prev 回溯。上例得到 `2, 3, 7, 18`（LIS 不唯一，`2, 5, 7, 101` 同样合法）。

## 4. 方法对比

| 维度     | DP                                             | patience sorting      |
| -------- | ---------------------------------------------- | --------------------- |
| 时间     | `O(n^2)`                                       | `O(nlogn)`            |
| 空间     | `O(n)`                                         | `O(n)`                |
| 方案重建 | prev 回溯，自然直接                            | 堆号 + 前驱回溯，稍绕 |
| 附带信息 | 完整 dp 数组（如 673 计数需要的以 i 结尾信息） | 只有长度免费          |
| 适用     | n 小或需要 dp 数组                             | n 大、只关心长度      |

## 5. 变体与应用

| 变体 / 应用                 | 要点                                                      |
| --------------------------- | --------------------------------------------------------- |
| LeetCode 300 最长递增子序列 | 模板题，两种方法都要会                                    |
| LeetCode 673 LIS 的个数     | DP 同时记「以 i 结尾的长度与个数」；O(nlogn) 版需树状数组 |
| LeetCode 354 俄罗斯套娃信封 | 二维偏序：宽升序、同宽高降序，再对高做 LIS                |
| patience sorting 本身       | 分堆 + k 路归并就是一个 `O(nlogn)` 排序算法               |
