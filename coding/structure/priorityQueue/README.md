# PriorityQueue（优先队列）

> 出队顺序按优先级而不是入队顺序（区别于普通队列的 FIFO）：每次出队一定是当前「最优先」的元素

[查看实现与示例](./index.ts)

在 `coding/structure/` 子包内使用 Node >= 22.18 运行：

```bash
pnpm priorityQueue
```

观察优先级出队、自定义比较器与 K 路归并。

## 1. 定义与性质

- 普通队列先进先出，优先队列按优先级出队：入队随意，出队永远取当前最优先的元素
- 「谁优先」由比较器定义：`compare(a, b) < 0` 表示 a 更优先 —— 默认「值越小越优先」，反转比较器即得「值越大越优先」
- 它是抽象数据类型（只定义接口语义），堆是实现它最常用的数据结构（见 [heap](../heap/README.md)）
  > 面试中两者经常混称：谈接口语义时说优先队列，谈底层实现时说堆
- 同优先级的元素之间出队顺序不保证（堆不稳定）；需要稳定顺序时，可把递增序号纳入比较器。
- 默认比较器使用数值相减，适用于可按此方式比较的数值；存任务对象或字符串时应显式传入比较器。空队列的 peek/poll 返回 undefined，offer 返回 void。

## 2. 实现选型

| 实现     | push      | poll      | 说明                             |
| -------- | --------- | --------- | -------------------------------- |
| 无序数组 | `O(1)`    | `O(n)`    | poll 时线性扫一遍找最值          |
| 有序数组 | `O(n)`    | `O(1)`    | 插入时挪位维持有序               |
| 二叉堆   | `O(logn)` | `O(logn)` | 两端都够快，综合最优 —— 标准选择 |

## 3. 核心操作

| 操作  | 语义                 | 复杂度    |
| ----- | -------------------- | --------- |
| offer | 入队一个元素         | `O(logn)` |
| poll  | 取出并删除最优先元素 | `O(logn)` |
| peek  | 只看不删最优先元素   | `O(1)`    |

接口与堆的 `push` / `pop` / `peek` 一一对应，换名字只是为了表达「按优先级出队」的语义。

## 4. 应用场景

| 场景                     | 优先级定义       | 要点                                            |
| ------------------------ | ---------------- | ----------------------------------------------- |
| 任务调度 / 定时器        | 优先级高、到期早 | OS 调度、消息队列延迟重试的基础模型             |
| Dijkstra / Prim / A*     | 代价最小         | 每轮取当前代价最小的节点                        |
| 合并 K 个有序链表 / 数组 | 值最小           | K 个头节点入队，poll 后补同路下一个，`O(nlogk)` |
| 霍夫曼编码 / 合并石子    | 值最小           | 贪心：每次取两个最小者合并                      |
