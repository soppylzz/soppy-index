# Knapsack（背包问题）

> 「容量限制下选物品求最值」的 DP 家族：状态 `dp[i][c]` 表示前 i 件、容量 c 的最优解，转移只有「不选 / 选」两种

[查看实现与示例](./index.ts)

在 `coding/structure/` 子包内使用 Node >= 22.18 运行：

```bash
pnpm knapsack
```

对比 0/1 背包、完全背包和组合数计数。

## 1. 定义与性质

- 0-1 背包：每件物品至多选一次
- 完全背包：每件物品可选任意次
- 多重背包：第 i 件至多选 cnt[i] 次 —— 按二进制拆成若干 0-1 物品
- 共同骨架：外层枚举物品、内层枚举容量，「选 / 不选」取 max
- 一维滚动数组是标准写法：容量正序还是倒序，取决于转移引用的是上一行还是本行

## 2. 状态与转移

`dp[i][c]`：前 i 件、容量 c 的最大价值（w、v 为当前物品的重量与价值）

0-1 背包引用上一行（这件最多选一次）：

$$
dp[i][c] = \max(dp[i-1][c],\ dp[i-1][c-w] + v)
$$

完全背包引用本行（允许重复选）：

$$
dp[i][c] = \max(dp[i-1][c],\ dp[i][c-w] + v)
$$

一维化记忆点：

- 0-1 背包容量倒序：防止本行刚更新的 dp[c-w] 被再次使用（相当于重复选）
- 完全背包容量正序：本行 dp[c-w] 正好表达「这件已经选过」
- 初始化：不要求装满时全 0；要求「恰好装满」则 dp[0] = 0、其余为 -Infinity 表示不可达

## 3. 变体对照

| 变体     | 转移引用              | 一维遍历顺序 |
| -------- | --------------------- | ------------ |
| 0-1 背包 | 上一行 `dp[i-1][c-w]` | 容量倒序     |
| 完全背包 | 本行 `dp[i][c-w]`     | 容量正序     |
| 多重背包 | 二进制拆包后同 0-1    | 容量倒序     |
| 分组背包 | 每组至多选一件        | 容量倒序     |

计数型需要重新定义状态与初始化，不能只把 max 字面替换成 `+`。例如正整数面额、每种可无限使用、凑出目标和的场景：`ways[0] = 1`，其他为 0；外层枚举面额、内层容量正序，统计不区分顺序的组合；外层容量正序、内层枚举面额，则统计区分顺序的序列。0-1 计数还需容量倒序，不能直接套用这个结论。

最值型转移只在 `c >= w` 时考虑“选”；否则沿用不选结果。当前示例假设容量为非负整数、重量或面额为正整数，零重量的无限物品会破坏状态模型。要求恰好装满时，最终状态仍为不可达值表示无解。

## 4. 应用场景

| 场景             | 对应变体 | 要点                                   |
| ---------------- | -------- | -------------------------------------- |
| 分割等和子集     | 0-1      | 目标和 sum/2 的可行性，dp[c] 存布尔    |
| 目标和（加减号） | 0-1 计数 | 转化为「和为 (sum+target)/2 的子集数」 |
| 零钱兑换         | 完全     | 最少件数：max 换 min，硬币可重复       |
| 零钱兑换 II      | 完全计数 | 外层币内层容量 => 组合数不重不漏       |
| 一和零           | 二维费用 | 容量变为 (0 的个数, 1 的个数) 两维     |
