# Deque（双端队列）

> 两端都能入队、出队的队列（double-ended queue），四种端点操作都是 `O(1)`；滑动窗口类问题的标准载体

[查看实现与示例](./index.ts)

在 `coding/structure/` 子包内使用 Node >= 22.18 运行：

```bash
pnpm deque
```

观察两端操作、回文检查和滑动窗口最大值。

## 1. 定义与性质

- Deque = double-ended queue：头尾两端都支持插入和删除，同时具备栈（同端进出）和队列（一端进另一端出）的能力
- 无固定 FIFO / LIFO 语义，按用法退化成栈或队列
- 要点在「两端都 `O(1)`」：这正是普通数组做不到的

## 2. 环形数组表示

定长数组 + `head` 指针 + `size` 计数：

- 逻辑位置 `i` 对应物理下标 `(head + i) % capacity` —— 越过数组末尾就绕回开头，逻辑上是一个环
- 队尾位置 = `(head + size - 1) % capacity`；两端操作只改 `head` 或 `size`，不搬动元素
- 空间满了倍增扩容：按逻辑顺序平铺到新数组，`head` 归零（均摊 `O(1)`）
- 对比 JS Array：`push` / `pop` 是 `O(1)`，但 `shift` / `unshift` 要整体挪动是 `O(n)` —— 这就是面试中自己实现 deque 的原因

## 3. 核心操作

| 操作                 | 语义        | 复杂度      |
| -------------------- | ----------- | ----------- |
| pushBack / pushFront | 尾 / 头入队 | `O(1)` 均摊 |
| popBack / popFront   | 尾 / 头出队 | `O(1)`      |
| peekBack / peekFront | 看尾 / 头   | `O(1)`      |
| size                 | 当前元素数  | `O(1)`      |

双端 + 单调性 = 单调队列：从尾入队时维持单调，从头部弹掉过期元素（见 [../monoStack/](../monoStack/)）。

## 4. 应用场景

| 场景                   | 用法                       | 要点                                      |
| ---------------------- | -------------------------- | ----------------------------------------- |
| 滑动窗口最大 / 最小值  | 单调队列                   | 尾部维持单调，头部弹过期下标，整体 `O(n)` |
| 0-1 BFS                | 权 0 加头部，权 1 加尾部   | 求 0/1 边权最短路，比 Dijkstra 轻         |
| 回文判断               | 两端成对弹出比较           | 头尾双指针思路的队列版                    |
| work-stealing 任务调度 | owner 操作尾，窃取者操作头 | Java ForkJoin / Go 调度器的底层模型       |
| 撤销 / 前进历史        | 尾部进，尾部退             | 超出上限时从头部淘汰                      |
