# Heap（堆）

> 完全二叉树 + 堆序性质：`O(1)` 拿最值、`O(logn)` 增删，是「Top K / 流式最值」类问题的标准武器


观察小顶堆、大顶堆、自定义比较器与 Top K。

## 1. 定义与性质

堆是一棵**完全二叉树**，且满足堆序性质：

- 大顶堆：每个节点 >= 它的孩子 → 堆顶是最大值
- 小顶堆：每个节点 <= 它的孩子 → 堆顶是最小值

大小关系只沿「父 → 子」这条边成立：

- 同层之间、两个子树之间没有任何顺序
  > 所以堆只回答「最值 / Top K」类问题，不能高效回答「任意第 k 小」
- 同一个集合的堆表示不唯一，只保证堆顶正确

## 2. 数组表示

完全二叉树可以无缝压进数组（层序存放），无需指针、缓存友好：

- 节点 `i`：左孩子 `2i + 1`，右孩子 `2i + 2`，父节点 `(i - 1) >> 1`
- 叶子节点区间 `[n >> 1, n - 1]`；最后一个非叶子节点是 `(n >> 1) - 1`（建堆的起点）

## 3. 核心操作

| 操作     | 做法                                                           | 复杂度     |
| -------- | -------------------------------------------------------------- | ---------- |
| peek     | 直接读 `data[0]`                                               | `O(1)`     |
| push     | 追加到尾部，siftUp 上浮                                        | `O(logn)`  |
| pop      | 尾元素补到堆顶，siftDown 下沉                                  | `O(logn)`  |
| heapify  | 从最后一个非叶子节点倒序逐个 siftDown                          | `O(n)`     |
| heapSort | 先 heapify，再反复「堆顶与未排序区末尾交换 + 范围内 siftDown」 | `O(nlogn)` |

- siftUp：新元素与父节点比，不满足堆序就交换，逐层向上直到满足
- siftDown：节点与两个孩子中**更优先的那个**比，不满足堆序就交换，逐层向下直到叶子
- heapify 为什么是 `O(n)` 而不是 `O(nlogn)`？
  > 逐个 push 是逐个上浮，总代价 `O(nlogn)`；倒序下沉时，一半节点是叶子（下沉 0 层），n/4 的节点最多下沉 1 层
  >
  > $$
  > \sum_{h=0}^{\log n} h \cdot \frac{n}{2^{h+1}} = O(n)
  > $$
  >
  > 直觉：大多数节点贴近底部、几乎不用动，只有顶部少数节点才真正下沉 logn 层

## 4. 应用场景

| 场景                | 用哪种堆         | 要点                                                |
| ------------------- | ---------------- | --------------------------------------------------- |
| 第 K 大 / 前 K 大   | 小顶堆，容量 K   | 堆顶是这 K 个里最小的，比堆顶大就替换 —— 最容易记反 |
| 第 K 小 / 前 K 小   | 大顶堆，容量 K   | 对称                                                |
| 数据流中位数        | 大顶堆 + 小顶堆  | 大顶堆存较小一半、小顶堆存较大一半，两堆大小差 <= 1 |
| 合并 K 个有序链表   | 小顶堆           | K 个头节点入堆，pop 出最小节点再把它的 next 入堆    |
| Dijkstra / Prim     | 小顶堆           | 稀疏图从 `O(V^2)` 优化到 `O((V+E)logV)`             |
| 任务调度 / 多路归并 | 按优先级定比较器 | 堆的本质就是优先队列                                |
