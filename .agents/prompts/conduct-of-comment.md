# Comments

Write comments in English, including JSDoc and embedded browser scripts. Explain reasoning, constraints, invariants, or surprising behavior that the code cannot communicate clearly.

- Improve an unclear name before adding a comment to explain it.
- Place comments beside the relevant code and update or remove them when behavior changes.
- Mention a rejected approach only when the reason will help a future reader avoid a real mistake.
- Use `//` for brief comments and `/** ... */` for API contracts or substantial explanations. Avoid decorative dividers and line-by-line narration.
- A short expected-result comment can clarify a subtle example; label nondeterministic or illustrative output. Keep extended teaching explanations in the Chinese note.
- Do not record edit history, task progress, or agent execution steps in source comments.
