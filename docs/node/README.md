# Node.js：从运行机制到服务实践

[仓库首页](../../README.md) · [公共 Demo](../demo/README.md)

先理解 JavaScript 在哪里执行、模块怎样加载，再看异步任务如何完成。掌握字节和流后，HTTP 服务、Worker、诊断与测试会更容易串起来。本节的概念说明与可运行实验配对：先读知识笔记并预测结果，再运行实验核对；一次运行中的时间和调度顺序只作为该次观察。

Node >= 22.18 可直接运行仓库中的可擦除 TypeScript。每组 README 给出命令；CLI 实验有限执行后退出，HTTP 服务需手动停止。Node 的事件循环与浏览器的渲染机会不同，不把浏览器的阶段图直接套在这里。已运行的版本、结果和限制见[验证记录](./validation.md)。

## 阅读实验输出

CLI 日志包含 UTC 时间、PID、事件名和数据。先按事件名与上下文核对断言：`lab-complete` 且退出码为 0 表示入口完成，`lab-failed` 表示入口失败。故意构造的拒绝会被实验单独捕获，不能把任何报错都当作预期。时间戳帮助关联事件，不证明不同进程或线程有全局顺序。

[lab.ts](./lab.ts) 提供 `log`、`runLab` 和有超时/输出上限的 `runNode`；具体资源仍由各实验负责关闭。HTTP 页面复用[公共 Demo](../demo/README.md) 的样式、logger 和服务端接口。这里的运行条件只针对本仓库；Node API 的一般行为以各篇链接的官方文档为准。
