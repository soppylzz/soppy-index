# 异步组合、事件与上下文：实验走查

[知识导航与运行命令](./README.md) · [完整实现](./index.ts)

先读相应笔记并预测，再运行完整入口。下表的“应看到”是这个实验控制条件下的检查点；实测环境与结果单独记录在[验证记录](../validation.md)。

| 问题                   | 看哪里                     | 应看到与原因                                                                        |
| ---------------------- | -------------------------- | ----------------------------------------------------------------------------------- |
| 并发上限限制了什么？   | 看六个任务和两个消费者     | 最多同时启动两个任务；分批等待已启动 Promise 不会实现这一限制。                     |
| 超时等于取消吗？       | 看 timer 的 AbortSignal    | 传入 signal 后产生 `AbortError`，`finally` 执行清理；只让等待超时不能停止底层任务。 |
| 事件监听何时运行？     | 比较 emit 前后与两个监听器 | `emit` 同步调用监听器；异步监听器的拒绝由 `captureRejections` 转到 error 路径。     |
| 并发请求会串上下文吗？ | 看两个 request store       | 不同 timer 交错后仍读到各自 ID；`run` 外读取不到该 store。                          |

这里没有运行第三方回调库、真实数据库或分布式 trace。实验中被捕获的拒绝是受控对照，不代表未知异常可以继续安全运行。
