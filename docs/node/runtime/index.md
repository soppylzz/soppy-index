# 运行时、事件循环与进程：实验走查

[知识导航与运行命令](./README.md) · [完整实现](./index.ts)

先读相应笔记并预测，再运行完整入口。下表的“应看到”是这个实验控制条件下的检查点；实测环境与结果单独记录在[验证记录](../validation.md)。

| 问题                      | 看哪里                  | 应看到与原因                                                                    |
| ------------------------- | ----------------------- | ------------------------------------------------------------------------------- |
| 进程由什么组成？          | 查 `components`         | 输出 Node、V8、libuv、平台与 PID；这些是版本信息，不代表某次 I/O 用了哪个线程。 |
| 微任务先后能否一概而论？  | 分别看 CJS/ESM 的 `top` | 同一注册代码处在不同顶层上下文；CJS 与 ESM 的 `nextTick`/Promise 顺序不同。     |
| 定时器与 Immediate 谁先？ | 看 `io`，再看顶层       | `readFile` 回调中的 Immediate 先到 check；顶层两者不作固定顺序断言。            |
| 进程怎样结束？            | 看退出事件与子进程状态  | 自然退出经历 body、beforeExit、exit；另一子进程的退出码 7 由父进程识别。        |

没有做线程池饱和、CPU 压力或进程管理器的 SIGTERM 演练；这里的退出事件不等于生产服务的完整关闭方案。
