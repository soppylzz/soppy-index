# 面试推演：沿场景解释机制与取舍

先独立说出问题发生在哪里，再对照提示补全。回答可以按“约束与现象 → 机制 → 方案与代价 → 验证和恢复”展开，不必背固定工具清单。

## 开发正常，生产构建后却白屏

先区分入口资源没加载、运行时抛错和业务内容未就绪。比较 dev/build 的条件入口、环境替换、插件阶段与语法目标，再用 release 和 map 还原异常。

追问：HTML 返回成功是否说明 JS 存在？旧标签页动态导入会请求哪个版本？怎样确认回滚能恢复？

参考：[工具工作方式](tooling/tools.md)、[发布顺序](tooling/delivery.md)、[白屏判断](monitoring/collection.md)。

## 引用了一个函数，为什么打包进了整个库

检查实际解析到了 ESM 还是 CJS、顶层副作用、导出访问方式和 sideEffects 配置，用产物分析确认保留原因。不要直接把整个包标记为无副作用。

追问：CSS 为什么消失？拆成多个 chunk 是否一定更快？Gzip 体积减小，执行时间为什么没下降？

参考：[模块图](tooling/modules.md)、[裁剪与分块](tooling/output.md)。

## 搜索框快速输入后，列表显示旧条件结果

画出两个请求和响应的时间顺序，区分取消请求与结果提交校验。查询键包含条件，提交前检查当前请求身份，旧结果不能覆盖当前意图。

追问：Abort 能撤销服务端写入吗？乐观更新第一次失败时，为什么不能直接恢复最早快照？切换账号后旧缓存怎么办？

参考：[状态与并发](architecture/state.md)、[请求层](architecture/requests.md)。

## 多个请求同时发现登录过期

先确认认证协议和可刷新条件，再共享一次刷新过程、限制重放、处理退出与账号切换。恢复成功不意味着任意写请求都可安全重试。

追问：刷新失败谁负责提示？请求体还能再次读取吗？登录回跳 URL 如何校验？前端隐藏按钮是否完成授权？

参考：[请求、路由与权限](architecture/requests.md)。

## 设计自动保存和离线编辑

分清服务端快照、编辑草稿和待同步操作，定义保存确认、基准版本、幂等和冲突体验。Debounce 只控制频率，不解决一致性。

追问：后台刷新能直接覆盖草稿吗？多标签页同时写怎样处理？恢复联网后为什么不能简单按本地时间覆盖？

参考：[表单](architecture/components.md)、[离线协议](architecture/resilience.md)。

## 页面打开慢，点击也卡

先分别测量加载与交互。将首屏拆成首字节、关键资源发现、传输和呈现；交互拆成输入等待、处理和下一次绘制。用瀑布图与 trace 指向瓶颈，再比较同条件数据。

追问：SSR 为什么不保证可交互？Promise 为什么不能可靠让出主线程？虚拟列表改善了什么，又增加哪些复杂度？

参考：[测量](perf/measurement.md)、[首屏](perf/loading.md)、[运行时](perf/runtime.md)。

## 设计前端监控，以及处理一次线上故障

从能采取的动作倒推采集：上下文关联 release/view/request，区分 JS、资源、HTTP 和业务失败，使用有界队列、脱敏与服务端去重。故障发生后先评估影响，再缓解、定位、验证和复盘。

追问：没有 error 是否说明没白屏？Beacon 返回 true 是否已送达？错误总数变少能否证明质量改善？SDK 的上报失败如何避免递归？

参考：[事件模型](monitoring/model.md)、[SDK](monitoring/sdk.md)、[故障响应](monitoring/operations.md)。

## 团队扩大后，是否需要 Monorepo 或微前端

先说协作与发布约束，再比较单应用模块化、拆包和独立部署。Monorepo 是仓库组织方式，微前端是应用集成与自治策略，二者可以独立选择。

追问：任务图与包图有什么区别？共享依赖版本冲突怎么办？迁移时谁是真值来源？哪些收益足以支付运行时复杂度？

参考：[依赖与 Monorepo](tooling/packages.md)、[架构演进](architecture/evolution.md)。
