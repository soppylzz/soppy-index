# 产物优化与 Source Map

一个导出没被使用，为什么仍出现在 bundle？因为“没有读取返回值”不代表“执行模块没有影响”。

## Tree Shaking 删除的前提

静态 ESM 有利于分析导出使用情况，工具据此结合副作用分析裁剪代码。模块顶层若注册事件、修改全局或导入样式，就不能仅因导出未使用而整体删除。

`sideEffects` 是包作者对文件副作用的声明。误写为 `false` 可能删掉必要样式或初始化；有副作用的入口和 CSS 应按实际匹配规则保留。压缩器的死代码删除与 Tree Shaking 会协作，但两者不等同。

可以把裁剪理解为“标记，再清理”：从入口执行和被使用导出出发保留必要依赖，再删除不可达且无副作用部分。真实工具采用不同算法，这一模型用于解释为什么未使用导出仍可能带着模块初始化一起保留。

Minify 是压缩过程的总称；compress 折叠或改写表达式，mangle 缩短可安全改名的标识符。它们处理的是源码表示，gzip/Brotli 处理的是传输字节，不能互相替代。

## 分块要匹配用户路径

订单列表首屏不需要导出 Excel 的全部代码，可以在用户进入该功能后动态导入。路由级拆分容易匹配访问路径，组件级适合低频重功能。

拆分太粗会增加首屏下载和执行，太细会增加请求、调度与串行等待。公共 chunk 能去重，也可能让简单页面被迫加载大依赖。应结合依赖分析与真实瀑布图判断，不能把所有第三方包无条件合成一个 vendor。

Content hash 应反映输出内容及影响引用的内容变化，用于区分不可变资源。原始体积、压缩传输体积与解析执行成本需分别看；gzip 后很小不代表执行便宜。

## Source Map 为什么必须匹配这次构建

Map 将生成文件的行列映射回原始位置，可包含 `sources`、`names`、`mappings` 和 `sourcesContent`。位置编码常用差量与 Base64 VLQ；多段转换必须组合各阶段 map，任意一层丢失都可能导致错位。

| 形式     | 适用考虑                         |
| -------- | -------------------------------- |
| Inline   | 调试方便，但把映射加入文件传输   |
| External | 独立文件，由关联注释供工具发现   |
| Hidden   | 不写公开关联注释，可上传监控平台 |

Hidden 不等于访问控制：若 map 仍能被公开下载，源码仍可能暴露。线上定位必须用对应 release、生成文件 URL/hash 和 map；不能把新代码套到旧映射上。

更多见 [Webpack Tree Shaking](https://webpack.js.org/guides/tree-shaking/)、[Source Map 标准](https://tc39.es/ecma426/)，线上排查见[版本与告警](../monitoring/operations.md)。
