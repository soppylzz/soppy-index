# 模块图：打包器怎样找到全部代码

订单入口引用列表，列表引用请求模块。打包器从入口递归访问这些依赖，把模块当节点、引用当边，形成 module graph。

## 解析不是字符串拼接

相对路径相对于 importer，也就是发起引用的模块；裸包名需要包解析规则。`exports` 描述包的公开入口与条件，`imports` 描述包内 `#` 映射；`main` 是旧式入口字段，并非只属于 CommonJS，`module`、`browser` 则是工具生态约定。

同一个包可能按 `import/require`、`node/browser` 等条件命中不同文件，条件还受顺序和工具支持影响。排错要记录请求字符串、importer、命中条件、最终路径和是否 external。

TypeScript 的路径提示不会自动重写运行时请求。alias 需要与构建器、测试工具和执行环境协调，否则编辑器能跳转，运行时仍找不到模块。

## 静态边与动态边

ESM 静态 import/export 让工具在不执行代码时识别多数依赖。`require(variable)` 或 `import(variable)` 的候选文件范围可能无法确定，需要工具约束或显式映射。

循环依赖不是递归无限执行：工具先登记节点再遍历，运行时也有模块身份与缓存。ESM 导入关联 live binding，初始化前读取可能触发暂时性死区；CommonJS 循环中可能读到部分初始化的导出。详细求值见 [Node 模块](../../node/modules/modules.md)。

## 从模块图变成 chunk 图

静态引用表达需要哪些模块，动态导入则常提供异步边界。多个路由共用请求模块，可以抽出共享 chunk；它们并非必须一模块一文件。

External 表示不把依赖实现打入当前结果，产物中的引用由消费环境继续解析。应用常打入依赖以便部署，库常 external 掉宿主框架，避免重复实例。

Scope hoisting 尝试将可合并的 ESM 放进更大的共同作用域，减少模块包装并增加跨模块优化机会；仍需保持绑定、执行顺序和副作用语义，不能简单拼接文件。

CSS、图片和 WASM 也进入构建链路：工具可以生成资源 URL、独立文件、内联数据或加载包装。内联节省请求，但扩大引用它的文件，并失去独立缓存边界，适用条件取决于体积与使用频率。

## 增量构建为什么会错

文件变动后，工具失效对应模块及受影响的转换或输出。缓存键除了源码，还要覆盖配置、插件版本、环境、目标平台和额外读入文件。漏掉一个输入，就可能得到“改了配置但产物没变”。

理解最小打包器时，可依次推演读取入口、解析依赖、登记模块、递归访问、转换、输出模块表与运行时。简化实现若用复制值模拟导入，不能声称完整实现 ESM live binding；生产级还要处理资源、条件解析、分块和错误恢复。

## 从最小模块表推到异步加载

同步教学模型可把模块转成函数表，由带缓存的 require 查找并执行。执行函数前先登记缓存，循环引用才能看到部分初始化结果，而不是无限递归。

异步模型还需区分模块与 chunk 的身份：manifest 将标识映射到文件 URL，runtime 加载并注册 chunk，再执行目标模块；并发请求同一 chunk 时应复用进行中的加载。文件写入磁盘并不意味着浏览器已有办法找到它。

这种模块表模型便于理解运行时，不能代替 ESM 的全部语义。推演时还应检查重复依赖、循环依赖、动态共享模块与加载失败，边界不明确时不要宣称实现了生产级打包器。
