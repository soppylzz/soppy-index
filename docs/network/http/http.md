# HTTP：语义、报文、缓存

## 一次请求到底表达什么

HTTP 方法说明意图，目标 URI 指定资源，请求字段提供条件和元数据，响应状态表示结果。HTTP/1.1 用文本形式的起始行、头、空行和消息体；HTTP/2/3 用二进制帧表示，但 GET、状态码、缓存控制等语义仍相通。

```http
GET /products/42 HTTP/1.1
Host: shop.example
Accept: application/json
If-None-Match: "p42-v3"

```

```http
HTTP/1.1 304 Not Modified
ETag: "p42-v3"
Cache-Control: private, max-age=60

```

此例表示客户端已有某个表示，询问它是否仍有效。`304` 不携带新的表示体，客户端结合本地缓存使用；如果没有可用缓存，孤立的 `304` 不能渲染页面。

## 方法与幂等

| 方法   | 典型含义                    | 安全/幂等要点                                  |
| ------ | --------------------------- | ---------------------------------------------- |
| GET    | 读取表示                    | 安全且幂等；别在 GET 上产生业务副作用          |
| HEAD   | 只取与 GET 对应的响应元数据 | 安全且幂等                                     |
| POST   | 提交由资源定义的处理        | 通常不保证幂等；支付重试需业务幂等键           |
| PUT    | 用完整表示创建/替换目标资源 | 幂等指重复请求的预期效果相同，不等于响应码相同 |
| PATCH  | 部分修改                    | 是否幂等取决于补丁语义                         |
| DELETE | 删除目标资源                | 语义幂等；第二次可返回不同状态                 |

“安全”指请求意图不要求改变服务器状态，并非无漏洞或不会产生日志。浏览器与中间件对重试的判断依赖这些语义，但业务必须实现相应约束。

## 状态码按问题读

`1xx` 表示中间信息，不应当成最终业务结果；例如 `100 Continue` 与请求体发送有关，HTTP/1.1 的 `101` 用于协议切换。最终响应才继续按下面几类理解。

- `2xx`：处理成功；`201` 常表示已创建，`204` 无响应体，`206` 是范围请求的部分内容。
- `3xx`：重定向/缓存协商；`301/308` 永久，`302/307` 临时，`307/308` 保留原方法和请求体；`304` 与条件请求一起读。
- `4xx`：客户端请求无法满足；`400` 语法或请求问题，`401` 需认证，`403` 拒绝授权，`404` 不存在或不愿公开，`409` 状态冲突，`429` 限流。
- `5xx`：服务器或上游处理失败；`502/503/504` 在网关场景常分别指无效上游响应、暂不可用、上游超时。具体故障仍看日志。

`401` 是“未通过认证或需认证”，`403` 是“已理解但拒绝授权”，不能靠状态码本身推断用户是否登录。

## 缓存的三件事

先判断响应能否存，再判断是否新鲜，过期后才考虑验证。`Cache-Control: max-age=60` 给出新鲜期；`no-cache` 允许存储但使用前要验证；`no-store` 要求不存储。`private` 限制共享缓存，不等于加密。`ETag` 配合 `If-None-Match`；`Last-Modified` 配合 `If-Modified-Since`。`Vary` 告诉缓存哪些请求字段影响表示；例如按 `Accept-Encoding` 变化。

不要以为请求头写了 `Cache-Control: no-cache` 就能控制所有层的缓存行为；CDN、浏览器 HTTP 缓存、Service Worker Cache Storage 和应用内缓存各有规则。浏览器实测见 [缓存实验](../../browser/cache/experiment.md)。

## 字段沿着什么方向传递

`Content-Type` 描述表示格式，`Content-Encoding` 描述压缩编码，`Transfer-Encoding` 是 HTTP/1.1 的消息传输机制，不要把三者混为一谈。Range/`206` 支持按字节取部分表示；断点续传还要处理实体变化与 `If-Range`。

把 header 按使用目的读更容易理解：`Host`/`:authority` 帮服务器选择站点；`Authorization` 表达认证信息；`Cookie` 由客户端携带符合策略的 Cookie；`Set-Cookie` 让浏览器按策略保存 Cookie。`Origin` 表达请求来源，`Location` 常配合重定向告诉客户端下一站。字段不保证都能由浏览器脚本自由设置或读取，Fetch 对此有专门限制。

`Connection`、HTTP/1.1 的 `Transfer-Encoding` 等是逐跳信息，中间代理需按规则处理；认证与 Cookie 也不能不加判断地转发给重定向后的其他站点。协议字段与应用随意起名的 `X-*` 字段不具有相同的通用语义。

跨源脚本读取响应还会经过 CORS 检查，某些请求先发送 OPTIONS 预检。这一过程拆到 [CORS 与预检](cors.md)，便于和普通 HTTP 请求响应分开理解。需要继续了解消息体何时结束、如何逐步读取，请读 [HTTP 传输](http-transfer.md)。
