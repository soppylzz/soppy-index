# 分层与一次请求

## 1. 为什么分层

网络要同时解决“电信号怎样走”“交给哪台机器”“交给哪个进程”“应用如何解释数据”等问题。分层使上层只依赖下层提供的服务。发送时每层加控制信息，接收时按层拆掉，叫封装与解封装。

| OSI 参考层       | 常用 TCP/IP 视角 | 本章例子                      | 要解决的问题               |
| ---------------- | ---------------- | ----------------------------- | -------------------------- |
| 应用、表示、会话 | 应用层           | DNS、HTTP、TLS、WebSocket     | 消息含义、编码、身份与会话 |
| 传输             | 传输层           | TCP、UDP                      | 进程到进程，可靠性或低开销 |
| 网络             | 网际层           | IPv4、IPv6、ICMP              | 跨网络寻址和转发           |
| 数据链路、物理   | 链路层           | Ethernet、Wi-Fi、ARP/邻居发现 | 一跳内交付与物理发送       |

这个对应只是教学近似：TLS 位于应用协议与传输之间；QUIC 在 UDP 上实现了传输功能；ARP 属于链路与网际层之间。面试不要把“七层模型”当成每个协议都能唯一归层的强制标准。

## 2. 从 URL 到页面

以首次访问 `https://shop.example/items` 为例：

1. 浏览器解析 URL，确定 scheme、主机、端口、路径；若命中可用缓存或 Service Worker，可能无需访问源站。
2. 系统通过 DNS 得到可用地址。DNS 名称是服务定位信息，不等同于一台固定机器；CDN、负载均衡会改变结果。
3. 选择目标 IP 与路由。目标在异网段时，链路帧发给下一跳网关；路由器按 IP 转发并重写下一跳的链路封装。
4. HTTP/1.1、HTTP/2 通常使用 TCP，HTTPS 再协商 TLS；HTTP/3 使用 UDP 上的 QUIC，其安全握手集成 TLS 1.3。
5. 浏览器发送 HTTP 请求，接收响应；状态、响应头和响应体共同决定缓存、解码与渲染。

“建立连接花了多久”必须结合协议版本和复用情况理解。一个页面的资源也可能走多个源、代理和连接。

## 3. 三种地址别混淆

- 域名方便服务定位，通过 DNS 解析；一个域名可有多个 IP，一个 IP 也可托管多个域名。
- IP 地址用于跨网寻址；NAT、负载均衡和 CDN 让用户看到的地址不必是最终应用实例地址。
- 端口标识主机上的传输层端点。通常用协议、源 IP/端口、目标 IP/端口描述一条传输流；TCP 连接由两端 IP/端口确定。

URL 的 host 参与 HTTP `Host`/`:authority` 与 TLS SNI；只用 IP 访问同一服务器，可能拿到错误站点或证书。

## 面试推演

若 DNS 查询成功但页面仍打不开，先用 `curl -v` 看连接和 TLS 阶段，再看 HTTP 状态与浏览器控制台。不要把 `ERR_CERT_*` 当成 DNS 问题，也不要把浏览器拦截响应误判为服务器未收到请求。下一篇先看 [IP 与 NAT](ip.md)。
