# TCP 进阶：序号、窗口、重传与异常

读完 [TCP/UDP 基础](transport.md)后，把“可靠”拆成可观察的四件事：字节编号、确认、窗口和重发。此篇不推导具体拥塞算法，只解释抓包时的因果链。

## 序号按字节走

假设 A 的初始序号为 1000，SYN 占一个序号；建立连接后发送 500 字节，起始序号是 1001，B 收齐后返回 `ACK=1501`，意思是“下一个期望字节为 1501”。ACK 是累计确认，不是“我刚收到第 1501 字节”。如果 B 先收到 1301–1500 而 1201–1300 缺失，它仍不能把连续确认推进到 1501；SACK 选项可以额外告知已收到的离散区间。

```text
A → B: seq=1001, len=200      B → A: ack=1201
A → B: seq=1201, len=100  丢失
A → B: seq=1301, len=200      B → A: ack=1201, SACK=1301..1501
A → B: 重传 1201..1301       B → A: ack=1501
```

这是教学时序；实际 ACK 合并、延迟确认、分段与重传策略会不同。Wireshark 的“TCP Retransmission”是分析器的推断标签，不能单独证明网络上真的丢包；双端抓包与时间戳更有说服力。

## 窗口解释“为什么不继续发”

接收方通告窗口 `rwnd`；发送方还受拥塞窗口 `cwnd` 与应用可用数据量限制。零窗口表示接收方暂时没有缓冲空间，发送方可用探测机制等待窗口重开；它不自动意味着链路坏了。窗口扩大选项在握手时协商，抓包中的原始 16 位字段与实际窗口大小不能直接等同。

RTT 是往返时间；RTO 是重传超时估计，需避免过早重传或久等。丢包可能由超时或重复 ACK/SACK 信号触发重传。吞吐可受小 `rwnd`、拥塞、应用读写、TLS/HTTP 排队等多因素限制，单看带宽数字不能下结论。

## 连接异常

- `RST` 立即中止连接，常见于端口无人监听、应用主动复位或中间设备干预；需结合方向与上下文判断。
- SYN 超时常指目标不可达、过滤或服务端无法回应；`ECONNREFUSED` 通常是收到明确拒绝，但实现与路径会影响表现。
- 半关闭允许一方向发送 FIN 后继续接收；应用协议若没有定义“何时消息结束”，不能把 FIN 当作唯一分隔符。
- Keepalive 是 TCP 连接探活机制，默认时间与开关由系统配置；HTTP `keep-alive` 是连接复用语义，二者不要混同。

## 抓包练习

启动一个你有权访问的 HTTP/1.1 测试服务，Wireshark 过滤 `tcp.port == 端口`；按 stream 查看 SYN 选项、序号、ACK、FIN。再刻意让客户端延迟读取响应，观察窗口变化；不要预设一定出现零窗口，因为操作系统缓冲和数据量会影响。主机网卡卸载会改变本机抓到的分段形态，必要时在网络另一端交叉验证。
